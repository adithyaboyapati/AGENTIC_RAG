2. System at a glance

Agentic RAG is a single canonical LangGraph workflow with strategy selection, evidence grading, verification, and production controls (auth, cache, guardrails, continuous evaluation). One question flows through classify → retrieve (or direct/web) → generate → verify → finalize.

4. End-to-end request lifecycle

4.1 Master flow

Client → middleware (RequestId, CORS, TrustedHost?) → verify_api_key + enforce_client_rate_limit → (sync) Idempotency-Key lookup → _resolve_chat_history → concurrency semaphore → run_agent / stream_agent A. PrivacyGuard.apply_input B. InputGuardrails.validate (+ injection scan) C. should_use_cache? D. augment_question_with_history E. cache hit? → post-guards → return F. CostGuardrails + record_query G. _dispatch → ask_canonical() H. OutputGuardrails + privacy output scan I. optional QualityGuardrails J. generate_follow_ups K. set_cached_response (pipeline_version keyed) L. production_observer hook (Phase 8) → _persist_exchange (Supabase if configured) → QueryResponse / SSE

4.2 Inside _dispatch

File: src/runner.py. Dispatch:

normalized = normalize_mode(mode)
if normalized == "source_tools":
    return ask_source_tools(question)
strategy = resolve_canonical_strategy(normalized)  # deprecated aliases → strategy
canonical = ask_canonical(question, force_strategy=strategy)
return canonical_to_api_response(canonical, display_mode="canonical")

On canonical failure with legacy_runtime_enabled=false (default): safe abstention response — no legacy graph replay.

5. Conversation memory

Memory packing in src/memory/chat_memory.py; optional Supabase persistence in supabase_store.py.

  1. Recent N exchanges: full Q+A (truncated).
  2. Older exchanges: questions only (topic trail).
  3. Wrapped into augment_question_with_history() before ask_canonical.
  4. Cache skipped when memory + non-empty history (answers must not leak across sessions).

7. LLM agents vs deterministic functions

LLM decision componentsDeterministic pipeline
Router (classify_query)Hybrid dense + BM25 + RRF fusion
Strategy selectorRetrieval plan execution
Document graderCross-encoder rerank (NVIDIA / FlashRank)
Query rewriterParent-child expansion, deduplication
GeneratorToken budgeting, citation index mapping
Verifier (optional LLM judge)SSRF-safe web fetch, RBAC filters
Two production graphs
Canonical path: extra sources federate into retrieve() — no LLM tool picker. mode=source_tools is a separate ReAct graph: the LLM chooses PDF / DB / API / MCP / calculator; PDF/DB/API/MCP hits are CRAG-graded before they become citations. Calculator is not graded.

8. Ingestion & retrieval

8.1 Ingestion

python -m src.ingestion.ingest --source data/sample_docs
→ cleanse → section_parent_child chunking → embed → Chroma upsert
→ parent_store.json → invalidate BM25 + flush cache

Async jobs: POST /ingest/jobs, upload: POST /ingest/upload. Registry: document_registry.py.

8.2 Retrieval (deterministic)

query → over-fetch candidate_k (hybrid: dense + BM25 → RRF) → optional rerank (nvidia API or flashrank local) → RBAC tenant/role filters → optional federation (SQLite / ops API / lab MCP) → parent expansion → evidence candidates for grading

Entry: execute_retrieval_plan() in src/retrieval/canonical_adapter.py.

9. Generation, verification, citations, streaming

  • Generation: LCEL chains in src/chains/generation.py; streaming via stream_text.
  • Verification: Always runs before finalize. Outcomes: PASS, WARN, FAIL. May abstain or append caveat.
  • Citations: citation_mapper.map_citations links evidence IDs to user-facing Citation objects.
  • Response status: answered | answered_with_warning | abstained.
  • API bridge: canonical_to_api_response() in src/contracts/api_response.py.
  • Follow-ups: generate_follow_ups attached by runner after successful non-abort runs.
